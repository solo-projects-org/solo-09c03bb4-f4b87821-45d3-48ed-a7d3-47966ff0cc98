# 跨馆标本目录对照

种质资源库数据员使用的网页工具：上传两馆同种标本 CSV，自动生成候选配对，
按"配对数量最多、其次日期差合计最小"求解，把候选分为**确定 / 待核 / 未匹配**，
支持馆员逐条确认或排除、重新计算、导出可导入的确定配对。

## 启动（Docker Compose）

```bash
docker compose up --build
# 浏览器打开 http://localhost:8000
```

数据保存在 compose 的数据卷 `catalog-data`（容器内 `/data/catalog.db`），
停止并重启容器后对照任务与馆员决定仍然保留。默认端口 8000，可改
`docker-compose.yml` 中的 `ports`。

镜像基于 `python:3.11-slim`，依赖见 `requirements.txt`。

## 本地运行（不使用容器）

```bash
python3 -m venv .venv && . .venv/bin/activate
pip install -r requirements.txt
uvicorn app.main:app --reload
# 默认数据库 data/catalog.db，可用 CATALOG_DB 环境变量指定
```

## 使用流程

1. 首页上传甲馆、乙馆两份 CSV（UTF-8 / UTF-8 BOM / GB18030 均可）。
2. 导入成功后进入对照详情页，按状态筛选：确定 / 待核 / 未匹配 / 已排除。
3. 对每条候选点"确认"或"排除"；也可"撤销"回退到自动判定。
   **每次决定与重算在同一事务内提交**：决定生效即得到新结果；
   矛盾决定（同一件标本被两条确认占用）或重算失败时整批回滚，
   页面提示原因，原有决定与结果保持不变。
4. "按现有决定重新计算"可随时重跑当前决定集合。
5. "下载确定配对 CSV"导出所有确定配对（含双方原文件行号），可直接导入。

结果表中的行号即上传文件中的物理行号（表头为第 1 行，空行和多行字段
按真实行号计数），点击可直接跳转到"原始文件"页面对应行。

## CSV 要求

必需四列（支持常见中英文别名）：

| 列 | 说明 |
| --- | --- |
| 馆藏号 | 同馆文件内必须唯一；重复时整份文件拒绝导入并提示重复行号 |
| 采集号 | 字符串，原样比较 |
| 县代码 | 字符串，原样比较（前导 0 保留） |
| 采集日期 | `YYYY-MM-DD`、`YYYY/MM/DD`、`YYYY.MM.DD`、`YYYYMMDD` 等 |

候选规则：采集号相同 **且** 县代码相同 **且** 采集日期相差 ≤ 1 天。
每件标本最多配对一次。

## 判定口径

在所有"配对数量最多、其次日期差合计最小"的最优方案中：

- **确定**：每一个最优方案都包含该配对，可导出。
- **待核**：至少一个最优方案包含、但不是全部包含；归属不唯一，需人工决定。
- **未匹配**：任何最优方案都不包含该配对。
- **已排除**：馆员显式排除，不再参与计算。

馆员确认的配对强制进入最优解，排除的配对禁止进入；其后其余候选仍在剩余
图上按同一目标重算。因此确认/排除后，"确定/待核"的判定是**基于含决定的
可行解空间**重新计算的。

实现：最小费用最大流（单位容量连续最短路）+ 残量图零约化代价强连通分量
判定每条边能否参加等代价重排；详见 `app/matching.py`。

## 测试

```bash
pip install pytest httpx   # 测试额外依赖
python -m pytest -q
```

- `tests/test_matching.py`：CSV 解析、行号、候选规则、目标函数与三态判定。
- `tests/test_bruteforce.py`：对全部 ≤3×3 小图穷举所有合法匹配，逐一比对
  配对数量、日期差合计与每条边的确定/待核/未匹配状态。
- `tests/test_web.py`：上传、重复馆藏号拒绝、确认/排除、矛盾回滚、
  重算失败回滚、导出内容与行号、原始文件页、404。

## 目录

```

app/domain.py      CSV 解析、日期与候选规则
app/matching.py    最优匹配与唯一性判定
app/db.py          SQLite 持久化、事务化决定与重算
app/templates/     Jinja2 页面
app/static/        样式
tests/             pytest 测试
```

## 已知限制

- 计算在单个进程内同步完成，超大目录（上万条候选）会让这一次请求变慢。
- 若决定记录无法同时满足（相互矛盾），或引擎无法给出结果，则整批回滚并
  保留上一次的决定与结果，页面会显示失败原因。
- 上传的原始 CSV 保存在 SQLite 中以便回看行号；单次导出的文件大小受
  FastAPI/Starlette 默认上传限制影响，超大目录建议分批。
- "待核"的数量等于"至少出现在一个最优方案、但并非所有最优方案都包含"的
  候选数；它在确认/排除后会按剩余可行解空间重新定义，因此数字可能变化。
